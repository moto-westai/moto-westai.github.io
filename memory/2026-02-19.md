## [22:25] Gantry Chat UI — Integration Complete

Jason gave green light for solo work on Gantry integration.

### What happened:
1. Verified OpenClaw `/v1/chat/completions` endpoint works (200 OK, SSE streaming confirmed)
2. Hit Docker networking wall — containers on custom networks can't reach host loopback (iptables isolation)
3. Tried: `host.docker.internal`, bridge IPs, TCP proxy — all blocked by Docker iptables
4. **Solution:** `network_mode: host` for backend container — gives direct access to all host services
5. Jason correctly pointed out OpenClaw chat endpoint routes through main agent session → would conflict with Discord/Telegram DMs
6. **Pivoted to Mac Mini MLX** (`192.168.4.30:8080`) — independent LLM backend, no session conflicts
7. Reset Jason's Gantry password (bcrypt via container)
8. **Full end-to-end test passed:** Login → create conversation → stream chat with Qwen3-Coder-30B ✅

### Final config:
- `.env`: `NEBULUS_LLM_URL=http://192.168.4.30:8080`
- `docker-compose.yml`: backend uses `network_mode: host`, ChromaDB at `127.0.0.1:8001`
- Frontend: `http://localhost:3001`
- Backend: `http://localhost:8000`
- LLM: Mac Mini MLX (Qwen3-Coder-30B, Llama-3.1-8B, Qwen2.5-Coder-32B)
- Original config backed up as `.env.backup-tabby`

### Key learnings:
- Docker custom networks + iptables = containers can't reach host loopback ports unless published or `network_mode: host`
- OpenClaw chat completions endpoint is full agent (memory, tools, personality) — not suitable for shared/independent chat UIs
- `host-gateway` maps to docker0 bridge (172.17.0.1), not actual host — still blocked by iptables
