## [15:56 CST] Context-Drip Incident — Jr. Resume Session

**Coined by:** Jason Jr. (schmibb)
**Term:** "context-drip" — cross-session message routing bleed

### What happened
1. Jr. sent a resume request from his DM session
2. It appeared as a "queued message" in Jason Sr.'s main session
3. I handled it inline and drafted replies — those replies went back through Sr.'s channel context, not Jr.'s
4. Attempted `message` tool with `target: 97289488627138560` (Jr.'s user ID) → "Unknown Channel" error
5. Eventually sent PDF to `channel:1473818142898917487` (Sr.'s DM channel) — it somehow delivered to Jr.'s DM view anyway
6. Jr. received both the routed messages AND the PDF successfully — but routing was confused throughout

### Root cause (hypothesis)
- OpenClaw queues messages from multiple users into the active session
- No automatic context boundary enforcement between user sessions
- `message` tool can't resolve user ID → DM channel ID for outbound DMs unless channel has been previously opened
- This is the same class of problem as the Agent DLP design — data flowing across session boundaries without enforcement

### Fix needed
- Agent DLP proxy: enforce session identity boundaries before message dispatch
- Or: OpenClaw needs to resolve user ID → DM channel ID at send time
- Short term: when handling queued messages from other users, explicitly route replies back through their session key

### Product note
This is now a documented real-world case study for the Agent DLP pitch. Jr. named it well.
